# Documentation Guidelines

Documentation is part of the implementation.

Maintain documentation for:

- requirements
- architecture
- data model
- API contract
- state machine
- UI flow
- test strategy
- setup instructions
- development workflow
- AI prompts
- AI mistakes and corrections

Never invent behavior that is not supported by the specification.

When behavior changes:

1. Update the specification.
2. Update affected design artifacts.
3. Update implementation.
4. Update tests.
5. Update documentation.

Documentation must remain consistent with the code and specification.
